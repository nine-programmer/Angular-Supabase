# Patterns — โครงสำเร็จรูปของระบบเล็กที่พบบ่อย

อ่านไฟล์นี้ก่อนเริ่มสัมภาษณ์ ถ้าไอเดียของผู้ใช้ตรงกับ pattern ใด ให้ **เสนอ** โครงนี้เป็นค่าเริ่มต้น แล้วถามแค่ว่า "ต่างจากนี้ตรงไหน" แทนการถามจากศูนย์

ทุก pattern ให้: ตาราง / ฟีเจอร์ MVP / สถานะ / ขั้นตอนหลัก / คำถามที่มักต้องถามเพิ่ม

เมื่อทำระบบประเภทใหม่เสร็จ ให้เพิ่ม pattern ลงท้ายไฟล์นี้

---

## P1. ระบบยืม–คืน (borrow/return)
คำที่บ่งบอก: ยืม, คืน, อุปกรณ์, หนังสือ, เครื่องมือ, ใครเอาไป

**ตาราง**
- `items` — id, name, code (รหัส), category, status (`available`/`borrowed`/`broken`), note
- `borrowers` — id, name, phone, department (ถ้าองค์กร)
- `loans` — id, item_id → items, borrower_id → borrowers, borrowed_at, due_at, returned_at (null = ยังไม่คืน), note

**ฟีเจอร์ MVP**
- F1 จัดการรายการของ (เพิ่ม/แก้/ลบ/ค้นหา)
- F2 บันทึกการยืม (เลือกของ + ผู้ยืม + กำหนดคืน) → status ของเป็น `borrowed`
- F3 บันทึกการคืน → returned_at, status กลับเป็น `available`
- F4 หน้ารวม: ของที่ถูกยืมอยู่ + ใครยืม + เกินกำหนดไหม

**สถานะของ:** available → borrowed → available (หรือ → broken)

**ขั้นตอนหลัก:** เปิดแอป → เห็นรายการของ + สถานะ → กด "ยืม" ที่ของ → กรอกผู้ยืม/กำหนดคืน → บันทึก → ของขึ้นว่า "ถูกยืม" → กด "คืน" → กลับเป็นว่าง

**ถามเพิ่ม:** ของแต่ละชิ้นมีหลายหน่วยไหม (ถ้ามี เพิ่มฟิลด์ `quantity` + `available_qty`) / ผู้ยืมต้องลงทะเบียนก่อนไหมหรือพิมพ์ชื่อสดๆ / ต้องแจ้งเตือนเกินกำหนดไหม (ปกติเลื่อนไปรอบถัดไป)

---

## P2. ระบบจองคิว (queue booking)
คำที่บ่งบอก: จองคิว, รับบัตรคิว, เรียกคิว, นัดหมาย, ช่วงเวลา

**ตาราง**
- `services` — id, name, duration_min, is_active
- `slots` (ถ้าจองตามช่วงเวลา) — id, service_id → services, date, start_time, capacity
- `bookings` — id, service_id → services, slot_id → slots (null ถ้าเป็นคิวเดินเข้า), customer_name, phone, queue_no, status (`waiting`/`called`/`done`/`cancelled`), booked_at, called_at

**ฟีเจอร์ MVP**
- F1 จัดการบริการ (เพิ่ม/แก้/ลบ)
- F2 ลูกค้าจองคิว (เลือกบริการ [+ วัน/เวลา] + ชื่อ + เบอร์) → ได้เลขคิว
- F3 หน้าเจ้าหน้าที่: เห็นคิววันนี้เรียงลำดับ + ปุ่ม เรียก / เสร็จ / ยกเลิก
- F4 หน้าจอแสดงคิว (คิวที่กำลังเรียก + คิวถัดไป) สำหรับติดหน้าร้าน

**สถานะคิว:** waiting → called → done (หรือ → cancelled จากทุกสถานะ)

**ขั้นตอนหลัก:** ลูกค้าเปิดลิงก์ → เลือกบริการ → กรอกชื่อ → ได้เลขคิว → เจ้าหน้าที่เห็นคิวใหม่ → กด "เรียก" → หน้าจอโชว์เลข → กด "เสร็จ"

**ถามเพิ่ม:** จองล่วงหน้าตามเวลา หรือรับคิวหน้างานเรียงลำดับ (ตัดสินว่ามี `slots` ไหม) / มีกี่ช่องบริการพร้อมกัน / เลขคิวรีเซ็ตทุกวันไหม (ปกติ: ใช่)

---

## P3. ระบบลงทะเบียน / รับสมัคร (registration)
คำที่บ่งบอก: ลงทะเบียน, สมัคร, กิจกรรม, อบรม, ผู้เข้าร่วม, เช็คชื่อ

**ตาราง**
- `events` — id, name, date, location, capacity, registration_open (bool)
- `registrations` — id, event_id → events, name, phone, email, extra (jsonb สำหรับคำถามเพิ่ม), status (`registered`/`checked_in`/`cancelled`), registered_at

**ฟีเจอร์ MVP**
- F1 จัดการกิจกรรม (เพิ่ม/แก้/ลบ/เปิด-ปิดรับสมัคร)
- F2 ฟอร์มลงทะเบียนสาธารณะ (1 ลิงก์ต่อกิจกรรม) → เต็มแล้วปิดอัตโนมัติ
- F3 รายชื่อผู้ลงทะเบียน + ค้นหา + ปุ่มเช็คชื่อ
- F4 ส่งออกรายชื่อเป็น CSV

**ขั้นตอนหลัก:** ผู้จัดสร้างกิจกรรม → ได้ลิงก์ → แชร์ → ผู้สมัครกรอก → ผู้จัดเห็นรายชื่อ → วันงานกดเช็คชื่อ

**ถามเพิ่ม:** ฟอร์มมีคำถามพิเศษอะไรบ้าง (ใส่ใน `extra`) / ต้องยืนยันทางอีเมลไหม (ปกติ: รอบถัดไป) / ซ้ำได้ไหม (ปกติ: เบอร์โทรซ้ำไม่ได้ในกิจกรรมเดียวกัน)

## P4. ระบบคลัง / นับสต็อก (inventory)
คำที่บ่งบอก: สต็อก, คลัง, รับเข้า, เบิกออก, จำนวนคงเหลือ, ของใกล้หมด

**ตาราง**
- `products` — id, name, sku, unit, min_qty (แจ้งเตือนเมื่อต่ำกว่า), current_qty
- `movements` — id, product_id → products, type (`in`/`out`/`adjust`), qty, note, moved_at

**ฟีเจอร์ MVP**
- F1 จัดการสินค้า (เพิ่ม/แก้/ลบ)
- F2 บันทึกรับเข้า / เบิกออก / ปรับยอด → `current_qty` เปลี่ยนตาม
- F3 หน้ารวม: คงเหลือทุกรายการ + ไฮไลต์ของต่ำกว่า `min_qty`
- F4 ประวัติการเคลื่อนไหวต่อสินค้า

**กติกาสำคัญ:** `current_qty` ห้ามแก้ตรงๆ ให้เปลี่ยนผ่าน `movements` เท่านั้น (Postgres function เรียกผ่าน `.rpc()` + `CHECK (current_qty >= 0)` ป้องกันกดพร้อมกัน)

**ถามเพิ่ม:** มีหลายคลังไหม (ถ้ามี เพิ่ม `locations`) / ต้องบันทึกราคาไหม / ใครเป็นคนเบิก (ถ้าต้องรู้ เพิ่ม `requested_by`)

---

## P5. รายการทั่วไป (simple CRUD list)
ใช้เมื่อผู้ใช้ต้องการแค่ "เก็บรายการ ___ แล้วดู/ค้นหา/แก้ได้"
คำที่บ่งบอก: เก็บข้อมูล, ทะเบียน, รายชื่อ, บันทึก, ฐานข้อมูล ___ เล็กๆ

**ตาราง**
- `<records>` — id, ฟิลด์ตามที่ผู้ใช้บอก, created_at, updated_at

**ฟีเจอร์ MVP**
- F1 ดูรายการทั้งหมด + ค้นหา + เรียง
- F2 เพิ่มรายการ
- F3 แก้ไข / ลบ
- F4 (ถ้าต้อง) กรองตามฟิลด์สำคัญ 1 ฟิลด์

**ถามเพิ่ม:** ฟิลด์อะไรบ้าง 5–8 ฟิลด์แรกที่สำคัญที่สุด / ฟิลด์ไหนใช้ค้นหาบ่อย / มีสถานะไหม
