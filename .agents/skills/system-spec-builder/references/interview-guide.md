# Interview Guide — ถามยังไงให้ได้ข้อมูลครบโดยไม่เหนื่อยผู้ใช้

ผู้ใช้ไม่ใช่โปรแกรมเมอร์ เขาตอบได้ดีเมื่อถามเรื่อง "งานที่ทำอยู่ทุกวัน" และตอบไม่ได้เมื่อถามเรื่อง "ระบบ" หน้าที่ของเราคือแปลงคำถามเชิงระบบให้เป็นคำถามเชิงงาน

## 1. หลักการ 6 ข้อ

| หลัก | ไม่ดี | ดี |
|---|---|---|
| เสนอก่อน แล้วถามว่าต่างตรงไหน | "ต้องการเก็บข้อมูลอะไรบ้าง?" | "ปกติระบบยืม-คืนจดของ / ผู้ยืม / วันคืน — ของคุณต้องจดอะไรเพิ่มไหม?" |
| ถามผ่านเคสจริง | "มี status อะไรบ้าง?" | "ครั้งล่าสุดที่มีคนมายืม เกิดอะไรขึ้นบ้างตั้งแต่เขาเดินมาจนเอาของมาคืน?" |
| 1 คำถาม = 1 การตัดสินใจ | "ใครใช้ ใช้บนอะไร ต้อง login ไหม?" | "ใครเป็นคนกดในระบบ — พนักงานคนเดียว หรือลูกค้ากดเองด้วย?" |
| ให้ตัวเลือก + ค่าเริ่มต้นเสมอ | "เลขคิวรีเซ็ตไหม?" | "เลขคิวเริ่ม 1 ใหม่ทุกวัน (ก) หรือนับต่อไปเรื่อยๆ (ข)? ถ้าไม่บอกผมใช้ (ก)" |
| ถามในสิ่งที่ยังไม่รู้เท่านั้น | ถามซ้ำสิ่งที่ pattern หรือคำตอบก่อนหน้าตอบแล้ว | ข้ามไป ใช้ค่าที่รู้แล้ว |
| ขอของจริงก่อนถามทีละช่อง | "ต้องเก็บฟิลด์อะไรบ้าง?" | "ถ้ามี Excel / รูปสมุดจด / แบบฟอร์มที่ใช้อยู่ ส่งมาได้เลย ผมจะดึงช่องข้อมูลจากนั้นแทนการถาม" |
| fact หาเอง ถามเฉพาะการตัดสินใจ | "ตอนนี้มีสถานะอะไรใน SPEC เดิมบ้าง?" (รอบ feature) | อ่าน `docs/SYSTEM_SPEC.md` / `src/shared/enums/` เอง แล้วถาม "จะเพิ่มสถานะ X ต่อจาก Y ใช่ไหม?" — แต่ห้ามอ่าน `.env` และห้ามเดากติกาธุรกิจจากโค้ด |
| ถามเฉพาะข้อที่ตอบได้ตอนนี้ | ถาม "ใครกดเปลี่ยนแต่ละสถานะ" ทั้งที่ยังไม่รู้ว่ามีสถานะอะไร | เคาะรายการสถานะรอบนี้ก่อน ค่อยถามคนกดรอบหน้า |
| สะท้อนกลับเมื่อคำตอบยาว | ถามข้อถัดไปทันที | "เข้าใจว่า: ของ 1 ชิ้นยืมได้ทีละคน แต่คนเดียวยืมหลายชิ้นได้ — ใช่ไหม?" |

## 2. เทคนิคหลัก: เดินตามเคสจริง 1 เคส

ถามภายในรอบแรกหรือรอบที่สอง:

> "ช่วยเล่าเคสจริงล่าสุด 1 เคสตั้งแต่ต้นจนจบ เช่น ใครมา ทำอะไร คุณจดอะไร แล้วจบยังไง"

จากเรื่องเล่า 1 เรื่อง ดึงออกมาได้:
- **entity + ฟิลด์** — ทุกคำนามที่ถูก "จด" (ชื่อ, เบอร์, ของ, วันคืน)
- **สถานะ** — ทุกคำที่บอกว่า "ตอนนี้อยู่ขั้นไหน" (รอ, กำลัง, เสร็จ, ยกเลิก)
- **กติกา** — ทุกครั้งที่เขาพูดว่า "ไม่ให้", "ต้อง", "ห้าม", "ถ้า...ก็"
- **บทบาท** — ใครเป็นคนทำแต่ละขั้น

แล้วถามต่อเฉพาะ "เคสที่ไม่ปกติ": "แล้วถ้าของหมด / ถ้าคนเดิมมาอีก / ถ้าจดผิดต้องแก้ ทำยังไง?"

ควบคู่กันในรอบเดียวกัน **ขอของจริง**: ไฟล์ Excel, รูปถ่ายสมุดหรือแบบฟอร์มกระดาษ, ข้อความ LINE ที่ใช้รับงานอยู่ ถ้าได้มา ให้ดึงออกเองก่อนถามต่อ:
- **ฟิลด์** = หัวคอลัมน์ / ช่องในฟอร์ม (แยกว่าช่องไหนกรอกทุกแถว = บังคับ)
- **รายการตายตัว** = คอลัมน์ที่ค่าซ้ำกันไม่กี่แบบ (หมวด, สาขา, สถานะ)
- **ห้ามซ้ำ** = คอลัมน์ที่ค่าไม่เคยซ้ำเลย (รหัส, เบอร์)
- **สถานะ** = คอลัมน์ที่มีค่าเปลี่ยนไปตามเวลา หรือแถวที่ขีดฆ่า / ไฮไลต์

จากนั้นถามเฉพาะสิ่งที่ไฟล์ไม่บอก: "คอลัมน์ 'หมายเหตุ' ใช้จดอะไร?" "แถวที่ไฮไลต์เหลืองคือขั้นไหน?" — และของจริงนี้คือคำตอบของ M12 ไปในตัว (จำนวนแถว = ข้อมูลเดิมที่ต้องนำเข้า)

## 3. คลังคำถามตามหัวข้อ (เลือกใช้เฉพาะที่ยังไม่รู้)

**M1 ปัญหา**
- "ตอนนี้ทำยังไงอยู่ — สมุด, Excel, LINE, จำเอา?" · "อะไรที่พังบ่อยที่สุดในวิธีปัจจุบัน?" · "ถ้าระบบนี้ใช้ได้ คุณจะเลิกทำอะไร?"

**M2 ผู้ใช้**
- "ใครกดในระบบบ้าง? มีคนที่ควรเห็นแต่ห้ามแก้ไหม?" · "ลูกค้า/คนนอกต้องเปิดเองจากมือถือไหม หรือพนักงานกดให้?" · "ถ้าไม่มี login แล้วใครก็เปิดหน้าพนักงานได้ รับได้ไหมในรอบแรก?" · ถ้ามี login: "เข้าแบบไหน — รหัสเดียวของร้าน / แต่ละคนมีบัญชี / OTP?" → ตัดสินว่ามีตารางผู้ใช้หรือไม่ (ลง 1.2) · "มีหน้าไหนที่คนทั่วไปกดส่งข้อมูลได้โดยไม่ล็อกอินไหม (จอง สมัคร ส่งฟอร์ม)? → ควรจำกัดกี่ครั้งต่อกี่นาที? (นับต่อ IP — ถ้าผู้ใช้ส่วนใหญ่อยู่ในเครือข่ายเดียวกัน เช่น ออฟฟิศ/โรงเรียน ทุกคนจะใช้ IP เดียวกัน ต้องตั้งจำนวนสูงขึ้น)" ถ้าผู้ใช้ไม่รู้ ใช้ค่าเริ่มต้นใน AGENTS แล้วบอกผู้ใช้ (ลง 2.4)

**M3 ฟีเจอร์**
- "จาก 4 อย่างนี้ [pattern] อันไหนไม่ต้อง อันไหนขาดไป?" · "ถ้าได้แค่ 3 อย่างในรอบแรก เอาอะไร?" · เมื่อผู้ใช้พูดถึงหน้าจอ: "หน้านั้นดูแล้วเอาไปตัดสินใจอะไรต่อ?"

**M4 ข้อมูล**
- "ต่อ 1 [รายการ] ต้องจดอะไรบ้าง 5 อย่างแรกที่ขาดไม่ได้?" · "อะไรที่ห้ามซ้ำ (รหัส, เบอร์, ชื่อ)?" · "ช่องไหนเป็นตัวเลือกตายตัว (เช่น หมวด) กับช่องไหนพิมพ์อะไรก็ได้?" · "ช่องไหนบังคับกรอก?"

**M5 จำนวน**
- "ของแต่ละอย่างมีชิ้นเดียว หรือมีหลายชิ้นเหมือนกัน (เช่น สาย HDMI 10 เส้น)?" · "คนเดียวเอาได้หลายอย่างพร้อมกันไหม?" · "มีจำกัดจำนวนต่อคน/ต่อวันไหม?"

**M6 สถานะ**
- "จาก [สถานะ pattern] มีขั้นไหนที่ร้านคุณไม่มี หรือมีเพิ่ม?" · "ย้อนกลับได้ไหม เช่น เสร็จแล้วกลับไปรอ?" · "ใครเป็นคนกดเปลี่ยนแต่ละขั้น?" · "ทุกครั้งที่เปลี่ยนขั้น ต้องจดเวลาหรือคนที่กดไว้ไหม?" · "รายการที่จบแล้ว ยังต้องเห็นอยู่ไหม นานแค่ไหน?"
- ถ้าไม่มี pattern ตรง ห้ามเดาสถานะ: "ตั้งแต่เรื่องเข้ามาจนจบ มีกี่ขั้น เรียกแต่ละขั้นว่าอะไร?"

**M7 ขั้นตอน** — ใช้เทคนิคข้อ 2 แล้วถามต่อ: "เปิดหน้าแรกอยากเห็นอะไรก่อน เรียงยังไง เห็นเฉพาะวันนี้ / เฉพาะที่ยังไม่จบไหม?"

**M8 กติกา (ระบบต้องปฏิเสธอะไร)**
- "กรอกซ้ำได้ไหม (คนเดิม/เบอร์เดิม/วันเดิม)?" · "เลือกวันย้อนหลังได้ไหม?" · "แก้ไขหลังจากจบแล้วได้ไหม ใครแก้ได้?" · "ยกเลิกได้ถึงขั้นไหน?"
- คำถามบังคับ: "ช่องกรอกไหนที่ระบบคำนวณตัวเลือกให้ (ช่องเวลา, ราคา, คนที่ว่าง, จำนวนคงเหลือ)?" → ทุกช่องแบบนี้ต้องมี R ที่ให้ server/DB ตรวจซ้ำว่าค่าที่ส่งมาอยู่ในรายการที่คำนวณได้จริง ไม่ใช่ตรวจแค่รูปแบบ — เขียน R นั้นลง 1.7
- คำถามเผยกติกาที่ผู้ใช้ลืมพูดเพราะ "ใครๆ ก็รู้": "ถ้าระบบทำอะไรผิดสักอย่างแล้วคุณจะเลิกใช้มันทันที อะไรคือสิ่งนั้น?" — คำตอบมักเป็นกติกาที่ต้องเข้า 1.7 (เช่น "ให้คนเดียวจองซ้อนสองคิว", "ลบประวัติหาย")
- เรื่องกดพร้อมกัน: ถ้า pattern มีกติกาแล้ว (P1–P4, P6) ใช้เป็นค่าเริ่มต้นและบอกผู้ใช้ตอนสรุป ไม่ต้องถาม; ถามเฉพาะเมื่อไม่มี pattern หรือเคสของผู้ใช้ต่างออกไป: "ถ้า 2 คนกดพร้อมกันตอนเหลือชิ้นเดียว ใครได้?"

**M9 การลบ**
- "ถ้าลบ [ของ/บริการ] ที่เคยมีประวัติ ประวัติเก่าต้องยังอยู่ไหม?" (ค่าเริ่มต้น: ซ่อนด้วย `is_active` ไม่ลบจริง)

**M10 เวลา**
- "มีอะไรที่เริ่มนับใหม่ทุกวัน/ทุกเดือนไหม?" · "มีเวลาเปิด-ปิดที่ระบบต้องรู้ไหม?" (timezone ใช้ `Asia/Bangkok` โดยไม่ต้องถาม)

**M11 เสร็จเมื่อ**
- "วันแรกที่ใช้จริง คุณจะลองทำอะไร 3 อย่างเพื่อเช็คว่าใช้ได้?" · "ถ้าใช้บนมือถือแล้วต้องซูม ถือว่ายังไม่ผ่านใช่ไหม?"

**M12 ข้อมูลเดิม / ขนาด**
- "มีรายการเดิมที่ต้องเอาเข้าไหม กี่รายการ อยู่ในรูปแบบไหน?" · "ต่อวันมีรายการใหม่ประมาณกี่รายการ?"
- "ข้อมูลเริ่มต้นที่ต้องมีจริงตั้งแต่วันแรก (ผู้ดูแลคนแรก, รายการประเภท, ข้อมูลจาก Excel เดิม) มีอะไรบ้าง?" · "ต้องการข้อมูลตัวอย่างไว้ทดลองใช้ไหม ถ้ามี ใครลบ และลบผ่านหน้าจอได้ไหม?" — คำตอบลง 1.9 (ถ้าไม่ถาม 1.9 จะว่างและ agent จะเดาเอง)

**M13 Deploy**
- "ให้ขึ้นบน Render (ค่าเริ่มต้น) หรือมีเซิร์ฟเวอร์ของตัวเองอยู่แล้ว?"

**M14 หน้าตา/สไตล์**
- "อยากให้หน้าตาโทนไหน — เรียบๆ แบบระบบในองค์กร หรือมีสีสัน? มีสีประจำองค์กรไหม?" · "มีแอปหรือเว็บที่ชอบหน้าตาอยู่แล้วไหม?" (ถ้าไม่บอก ใช้โทนเรียบ สะอาด น้ำเงิน-เทา — จดใน 1.9; ยังไงตอนสร้างจะมี Task Design ทำ mockup ให้ดูและแก้ได้ก่อนเริ่มหน้าจอจริง จึงไม่ต้องเค้นคำตอบละเอียดตอนสัมภาษณ์)

**M15 ฐานข้อมูล + ชื่อโปรเจกต์ — คำถามสุดท้ายเสมอ ถามแยกเทิร์นเดียวหลังข้ออื่นครบ ไม่มีค่าเริ่มต้น**
- ถามแบบนี้ (2 ตัวเลือก อธิบายเป็นภาษาชาวบ้าน ไม่ต้องอธิบายเทคนิค): "ข้อสุดท้าย — ฐานข้อมูลจะเก็บไว้ที่ไหน? (1) **Supabase cloud**: สมัครที่ supabase.com แล้วใช้ได้เลย ไม่ต้องดูแล server เอง (แบบมาตรฐานของ template) หรือ (2) **เซิร์ฟเวอร์ของตัวเอง (VPS)**: มี server อยู่แล้วหรืออยากเก็บข้อมูลไว้ในเครื่องของตัวเอง ต้องติดตั้ง PostgreSQL + PostgREST เอง (มีขั้นตอนใน README ให้ทำตาม) — Task 1 จะพาตั้งค่าตามที่เลือก"
- ในข้อความเดียวกัน เสนอชื่อโปรเจกต์ให้เคาะ ไม่ให้ผู้ใช้คิดเอง: "และผมจะตั้งชื่อโปรเจกต์ว่า `barber-queue` (ใช้เป็นชื่อโปรเจกต์บน Supabase หรือชื่อฐานข้อมูล `barber_queue` บน server ของคุณ และชื่อโฟลเดอร์ build) ตกลงไหม?" — slug เป็นภาษาอังกฤษตัวเล็ก คั่นด้วย `-` สั้นๆ 2–3 คำจากชื่อระบบ
- คำตอบทั้งสองลง SYSTEM_SPEC 2.1 (ไม่ใช่ 1.9 เพราะไม่ใช่การเดา) และทวนอีกครั้งตอนสรุปก่อนเขียน; ถ้าผู้ใช้บอกไว้แล้วตั้งแต่ต้นว่าฐานข้อมูลอยู่ที่ไหน ไม่ต้องถามซ้ำ แค่ทวน + เคาะ slug; มีโปรเจกต์ Supabase หรือฐานข้อมูลอยู่แล้วก็ได้ — จดชื่อจริงใน 2.1 slug ใช้แค่กับ repo; รอบ feature ไม่ถาม เพราะฐานข้อมูลเชื่อมแล้ว

## 5. สัญญาณว่าพอแล้ว

หยุดถามเมื่อ: M1 (ปัญหา), M4 (ข้อมูลหลัก), M7 (เคสจริง 1 เคส) มีคำตอบชัด, ข้อ ✗ อื่นมีคำตอบหรือผู้ใช้สั่งข้ามอย่างชัดเจน, กติกาเรื่อง "พร้อมกัน / ซ้ำ / ลบ" มีคำตอบหรือค่าเริ่มต้นจาก pattern, และไม่มีคำตอบที่ขัดกันค้างอยู่ — แม้จะถามไปแค่ 5 ข้อก็หยุดได้ จากนั้นถาม M15 (ฐานข้อมูล + ชื่อโปรเจกต์) เป็นข้อสุดท้ายแยกเทิร์นเดียว แล้วจึงไปสรุป

## 6. ตัวอย่างบทสนทนา (ระบบยืมอุปกรณ์ในออฟฟิศ, pattern P1, 3 รอบ 9 คำถาม + คำถามสุดท้าย M15)

**รอบ 1** — M1, M7, M5
> ระบบยืม-คืนปกติมี ของ / ผู้ยืม / รายการยืม และทำได้ 4 อย่าง: จัดการของ, บันทึกยืม, บันทึกคืน, ดูว่าใครยืมอะไรค้าง
> 1. ตอนนี้จดการยืมยังไง (สมุด/Excel/LINE) แล้วอะไรพังบ่อยที่สุด?
> 2. ช่วยเล่าครั้งล่าสุดที่มีคนมายืมของ ตั้งแต่เขาเดินมาจนเอามาคืน คุณจดอะไรบ้าง? (เล่ายาวได้ — และถ้ามีไฟล์ Excel ที่ใช้อยู่ ส่งมาได้เลย ผมจะดึงช่องข้อมูลจากไฟล์แทนการถามทีละช่อง)
> 3. ของแต่ละอย่างมีชิ้นเดียว หรือมีหลายชิ้นเหมือนกัน เช่น สาย HDMI 10 เส้น? (ถ้าไม่บอก ถือว่าชิ้นเดียว)

**รอบ 2** — สะท้อนกลับ (รวมสิ่งที่อ่านได้จากไฟล์) + M2, M8, M9 (ไม่ถามเรื่องกดพร้อมกัน เพราะ P1 มีกติกาแล้ว; ยังไม่ถามว่าใครกดเปลี่ยนสถานะ เพราะรายการสถานะเพิ่งชัดรอบนี้)
> เข้าใจว่า: จดใน Excel แต่ลืมอัปเดตตอนคืน ทำให้ไม่รู้ว่าของอยู่ไหน; จากไฟล์เห็น 6 คอลัมน์ (รหัสของ, ชื่อของ, ผู้ยืม, แผนก, วันยืม, วันคืน) รหัสของไม่ซ้ำเลย แผนกมี 4 ค่า และแถวไฮไลต์เหลืองคือยังไม่คืน; บางอย่างมีหลายชิ้น และบางทีคืนไม่ครบ — ใช่ไหม?
> 4. ใครเป็นคนกดในระบบ — แอดมินคนเดียว หรือพนักงานทุกคนกดยืมเอง? (ถ้าไม่บอก ถือว่าแอดมินคนเดียว ไม่มี login)
> 5. ยืมแล้วต้องมีวันกำหนดคืนทุกครั้งไหม? (ถ้าไม่บอก ถือว่ามี และเกินกำหนดต้องเห็นเป็นสีแดง)
> 6. ถ้าเลิกใช้ของที่เคยถูกยืม ประวัติเก่าต้องยังอยู่ไหม? (ถ้าไม่บอก จะซ่อนแทนลบ)

**รอบ 3** — M3 (สิ่งที่ไม่ทำ), M11, M12+M13
> 7. รอบแรกผมจะยังไม่ทำ login, แจ้งเตือนเกินกำหนด, รายงานสรุป — มีอะไรใน 3 อย่างนี้ที่ขาดไม่ได้ไหม?
> 8. วันแรกที่ใช้จริง คุณจะลองทำอะไร 3 อย่างเพื่อเช็คว่าใช้ได้? (ถ้าไม่บอก ผมใช้: ยืมจนหมดแล้วยืมไม่ได้, คืนแล้วยืมได้อีก, ดูรายการค้างบนมือถือ)
> 9. มีรายการของเดิมใน Excel ที่ต้องเอาเข้าไหม กี่รายการ? (ถ้าไม่บอก ถือว่าเริ่มจากว่าง)

**รอบ 4** — M15 (ข้อสุดท้าย ถามแยกเทิร์น)
> 10. ข้อสุดท้าย — ฐานข้อมูลจะเก็บไว้ที่ไหน? (1) Supabase cloud: สมัครที่ supabase.com แล้วใช้ได้เลย ไม่ต้องดูแล server เอง หรือ (2) เซิร์ฟเวอร์ของตัวเอง: ต้องติดตั้ง PostgreSQL + PostgREST เอง (มีขั้นตอนใน README) — และผมจะตั้งชื่อโปรเจกต์ว่า `office-loan` (ชื่อโปรเจกต์บน Supabase / ชื่อฐานข้อมูล `office_loan`) ตกลงไหม?

→ M1/M4/M7 ครบจากข้อ 1–3 (M4 ส่วนใหญ่มาจากไฟล์ Excel ไม่ใช่จากการถาม), ข้ออื่นมีคำตอบหรือค่าเริ่มต้น (M13 deploy และ M14 สไตล์ไม่ได้ถาม ใช้ Render + โทนเรียบ), M15 ตอบแล้ว (ลง 2.1) → เล่าย้อนเป็นเรื่อง 1 วัน ("เช้าวันจันทร์คุณเปิดหน้าแรก เห็นรายการที่ยังไม่คืนเรียงตามวันครบกำหนด รายการเกินกำหนดเป็นสีแดง สมชายมายืมสาย HDMI 2 เส้น คุณกดยืม เลือกชื่อเขา ใส่จำนวน 2 ระบบเตือนถ้าเหลือไม่พอ ...") + รายการ "ค่าที่ผมเลือกให้" แยกต่างหาก (กดพร้อมกันใช้กติกา P1, timezone ไทย, Render, โทนเรียบรอเคาะจริงตอน Task Design) → รอยืนยัน → เขียน
