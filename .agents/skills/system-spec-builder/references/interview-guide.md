# Interview Guide — ถามยังไงให้ได้ข้อมูลครบโดยไม่เหนื่อยผู้ใช้

ผู้ใช้ไม่ใช่โปรแกรมเมอร์ เขาตอบได้ดีเมื่อถามเรื่อง "งานที่ทำอยู่ทุกวัน" และตอบไม่ได้เมื่อถามเรื่อง "ระบบ" หน้าที่ของเราคือแปลงคำถามเชิงระบบให้เป็นคำถามเชิงงาน

## 1. หลักการ 6 ข้อ

| หลัก | ไม่ดี | ดี |
|---|---|---|
| เสนอก่อน แล้วถามว่าต่างตรงไหน | "ต้องการเก็บข้อมูลอะไรบ้าง?" | "ปกติระบบยืม-คืนจดของ / ผู้ยืม / วันคืน — ของคุณต้องจดอะไรเพิ่มไหม?" |
| ถามผ่านเคสจริง | "มี status อะไรบ้าง?" | "ครั้งล่าสุดที่มีคนมายืม เกิดอะไรขึ้นบ้างตั้งแต่เขาเดินมาจนเอาของมาคืน?" |
| 1 คำถาม = 1 การตัดสินใจ | "ใครใช้ ใช้บนอะไร ต้อง login ไหม?" | "ใครเป็นคนกดในระบบ — พนักงานคนเดียว หรือลูกค้ากดเองด้วย?" |
| ให้ตัวเลือก + ค่าเริ่มต้นเสมอ | "เลขคิวรีเซ็ตไหม?" | "เลขคิวเริ่ม 1 ใหม่ทุกวัน (ก) หรือนับต่อไปเรื่อยๆ (ข)? ถ้าไม่บอกผมใช้ (ก)" |
| ถามในสิ่งที่ยังไม่รู้เท่านั้น | ถามซ้ำสิ่งที่ pattern หรือคำตอบก่อนหน้าตอบแล้ว | ข้ามไป ใช้ค่าที่รู้แล้ว |
| สะท้อนกลับเมื่อคำตอบยาว | ถามข้อถัดไปทันที | "เข้าใจว่า: ของ 1 ชิ้นยืมได้ทีละคน แต่คนเดียวยืมหลายชิ้นได้ — ใช่ไหม?" |

## 2. เทคนิคหลัก: เดินตามเคสจริง 1 เคส

ถามภายในรอบแรกหรือรอบที่สอง:

> "ช่วยเล่าเคสจริงล่าสุด 1 เคสตั้งแต่ต้นจนจบ เช่น ใครมา ทำอะไร คุณจดอะไร แล้วจบยังไง"

จากเรื่องเล่า 1 เรื่อง ดึงออกมาได้:
- **entity + ฟิลด์** — ทุกคำนามที่ถูก "จด" (ชื่อ, เบอร์, ของ, วันคืน)
- **สถานะ** — ทุกคำที่บอกว่า "ตอนนี้อยู่ขั้นไหน" (รอ, กำลัง, เสร็จ, ยกเลิก)
- **กติกา** — ทุกครั้งที่เขาพูดว่า "ไม่ให้", "ต้อง", "ห้าม", "ถ้า...ก็"
- **บทบาท** — ใครเป็นคนทำแต่ละขั้น

แล้วถามต่อเฉพาะ "เคสที่ไม่ปกติ": "แล้วถ้าของหมด / ถ้าคนเดิมมาอีก / ถ้าจดผิดต้องแก้ ทำยังไง?"

## 3. คลังคำถามตามหัวข้อ (เลือกใช้เฉพาะที่ยังไม่รู้)

**M1 ปัญหา**
- "ตอนนี้ทำยังไงอยู่ — สมุด, Excel, LINE, จำเอา?" · "อะไรที่พังบ่อยที่สุดในวิธีปัจจุบัน?" · "ถ้าระบบนี้ใช้ได้ คุณจะเลิกทำอะไร?"

**M2 ผู้ใช้**
- "ใครกดในระบบบ้าง? มีคนที่ควรเห็นแต่ห้ามแก้ไหม?" · "ลูกค้า/คนนอกต้องเปิดเองจากมือถือไหม หรือพนักงานกดให้?" · "ถ้าไม่มี login แล้วใครก็เปิดหน้าพนักงานได้ รับได้ไหมในรอบแรก?"

**M3 ฟีเจอร์**
- "จาก 4 อย่างนี้ [pattern] อันไหนไม่ต้อง อันไหนขาดไป?" · "ถ้าได้แค่ 3 อย่างในรอบแรก เอาอะไร?" · เมื่อผู้ใช้พูดถึงหน้าจอ: "หน้านั้นดูแล้วเอาไปตัดสินใจอะไรต่อ?"

**M4 ข้อมูล**
- "ต่อ 1 [รายการ] ต้องจดอะไรบ้าง 5 อย่างแรกที่ขาดไม่ได้?" · "อะไรที่ห้ามซ้ำ (รหัส, เบอร์, ชื่อ)?" · "ช่องไหนเป็นตัวเลือกตายตัว (เช่น หมวด) กับช่องไหนพิมพ์อะไรก็ได้?" · "ช่องไหนบังคับกรอก?"

**M5 จำนวน**
- "ของแต่ละอย่างมีชิ้นเดียว หรือมีหลายชิ้นเหมือนกัน (เช่น สาย HDMI 10 เส้น)?" · "คนเดียวเอาได้หลายอย่างพร้อมกันไหม?" · "มีจำกัดจำนวนต่อคน/ต่อวันไหม?"

**M6 สถานะ**
- "จาก [สถานะ pattern] มีขั้นไหนที่ร้านคุณไม่มี หรือมีเพิ่ม?" · "ย้อนกลับได้ไหม เช่น เสร็จแล้วกลับไปรอ?" · "ใครเป็นคนกดเปลี่ยนแต่ละขั้น?" · "ทุกครั้งที่เปลี่ยนขั้น ต้องจดเวลาหรือคนที่กดไว้ไหม?" · "รายการที่จบแล้ว ยังต้องเห็นอยู่ไหม นานแค่ไหน?"
- ถ้าไม่มี pattern ตรง ห้ามเดาสถานะ: "ตั้งแต่เรื่องเข้ามาจนจบ มีกี่ขั้น เรียกแต่ละขั้นว่าอะไร?"

**M7 ขั้นตอน** — ใช้เทคนิคข้อ 2 แล้วถามต่อ: "เปิดหน้าแรกอยากเห็นอะไรก่อน เรียงยังไง เห็นเฉพาะวันนี้ / เฉพาะที่ยังไม่จบไหม?"

**M8 กติกา (ระบบต้องปฏิเสธอะไร)**
- "กรอกซ้ำได้ไหม (คนเดิม/เบอร์เดิม/วันเดิม)?" · "เลือกวันย้อนหลังได้ไหม?" · "แก้ไขหลังจากจบแล้วได้ไหม ใครแก้ได้?" · "ยกเลิกได้ถึงขั้นไหน?"
- เรื่องกดพร้อมกัน: ถ้า pattern มีกติกาแล้ว (P1–P4, P6) ใช้เป็นค่าเริ่มต้นและบอกผู้ใช้ตอนสรุป ไม่ต้องถาม; ถามเฉพาะเมื่อไม่มี pattern หรือเคสของผู้ใช้ต่างออกไป: "ถ้า 2 คนกดพร้อมกันตอนเหลือชิ้นเดียว ใครได้?"

**M9 การลบ**
- "ถ้าลบ [ของ/บริการ] ที่เคยมีประวัติ ประวัติเก่าต้องยังอยู่ไหม?" (ค่าเริ่มต้น: ซ่อนด้วย `is_active` ไม่ลบจริง)

**M10 เวลา**
- "มีอะไรที่เริ่มนับใหม่ทุกวัน/ทุกเดือนไหม?" · "มีเวลาเปิด-ปิดที่ระบบต้องรู้ไหม?" (timezone ใช้ `Asia/Bangkok` โดยไม่ต้องถาม)

**M11 เสร็จเมื่อ**
- "วันแรกที่ใช้จริง คุณจะลองทำอะไร 3 อย่างเพื่อเช็คว่าใช้ได้?" · "ถ้าใช้บนมือถือแล้วต้องซูม ถือว่ายังไม่ผ่านใช่ไหม?"

**M12 ข้อมูลเดิม / ขนาด**
- "มีรายการเดิมที่ต้องเอาเข้าไหม กี่รายการ อยู่ในรูปแบบไหน?" · "ต่อวันมีรายการใหม่ประมาณกี่รายการ?"

**M13 Deploy**
- "ให้ขึ้นบน Render (ค่าเริ่มต้น) หรือมีเซิร์ฟเวอร์ของตัวเองอยู่แล้ว?"

**M14 หน้าตา/สไตล์**
- "อยากให้หน้าตาโทนไหน — เรียบๆ แบบระบบในองค์กร หรือมีสีสัน? มีสีประจำองค์กรไหม?" · "มีแอปหรือเว็บที่ชอบหน้าตาอยู่แล้วไหม?" (ถ้าไม่บอก ใช้โทนเรียบ สะอาด น้ำเงิน-เทา — จดใน 1.9; ยังไงตอนสร้างจะมี Task Design ทำ mockup ให้ดูและแก้ได้ก่อนเริ่มหน้าจอจริง จึงไม่ต้องเค้นคำตอบละเอียดตอนสัมภาษณ์)

## 4. สัญญาณว่าต้องถามต่อ

| ได้ยิน | ถามต่อว่า |
|---|---|
| "ประมาณ / น่าจะ / แล้วแต่" | "ยกตัวอย่างกรณีที่ต่างกันให้ฟังหน่อย" |
| "ปกติ..." | "แล้วกรณีไม่ปกติล่ะ เกิดบ่อยไหม ต้องรองรับในรอบแรกไหม?" |
| "คนอื่น / หลายคน / หลายอย่าง" | "กี่คน/กี่อย่าง และต่างกันตรงไหน?" |
| "มีหน้ารายงาน / dashboard" | "ดูรายงานแล้วตัดสินใจอะไร? ตัวเลขไหนสำคัญที่สุด 1 ตัว?" |
| "ทุกอย่างที่ทำได้ตอนนี้" | "ขอ 3 อย่างที่ทำบ่อยที่สุด ที่เหลือไว้รอบถัดไป" |
| คำตอบขัดกับคำตอบก่อนหน้า | "เมื่อกี้บอก A ตอนนี้บอก B — อันไหนถูก หรือมีทั้งสองแบบ?" |

## 5. สัญญาณว่าพอแล้ว

หยุดถามเมื่อ: M1 (ปัญหา), M4 (ข้อมูลหลัก), M7 (เคสจริง 1 เคส) มีคำตอบชัด, ข้อ ✗ อื่นมีคำตอบหรือผู้ใช้สั่งข้ามอย่างชัดเจน, กติกาเรื่อง "พร้อมกัน / ซ้ำ / ลบ" มีคำตอบหรือค่าเริ่มต้นจาก pattern, และไม่มีคำตอบที่ขัดกันค้างอยู่ — แม้จะถามไปแค่ 5 ข้อก็หยุดได้

## 6. ตัวอย่างบทสนทนา (ระบบยืมอุปกรณ์ในออฟฟิศ, pattern P1, 3 รอบ 9 คำถาม)

**รอบ 1** — M1, M7, M5
> ระบบยืม-คืนปกติมี ของ / ผู้ยืม / รายการยืม และทำได้ 4 อย่าง: จัดการของ, บันทึกยืม, บันทึกคืน, ดูว่าใครยืมอะไรค้าง
> 1. ตอนนี้จดการยืมยังไง (สมุด/Excel/LINE) แล้วอะไรพังบ่อยที่สุด?
> 2. ช่วยเล่าครั้งล่าสุดที่มีคนมายืมของ ตั้งแต่เขาเดินมาจนเอามาคืน คุณจดอะไรบ้าง? (เล่ายาวได้)
> 3. ของแต่ละอย่างมีชิ้นเดียว หรือมีหลายชิ้นเหมือนกัน เช่น สาย HDMI 10 เส้น? (ถ้าไม่บอก ถือว่าชิ้นเดียว)

**รอบ 2** — สะท้อนกลับ + M2, M8, M9 (ไม่ถามเรื่องกดพร้อมกัน เพราะ P1 มีกติกาแล้ว)
> เข้าใจว่า: จดใน Excel แต่ลืมอัปเดตตอนคืน ทำให้ไม่รู้ว่าของอยู่ไหน; บางอย่างมีหลายชิ้น และบางทีคืนไม่ครบ — ใช่ไหม?
> 4. ใครเป็นคนกดในระบบ — แอดมินคนเดียว หรือพนักงานทุกคนกดยืมเอง? (ถ้าไม่บอก ถือว่าแอดมินคนเดียว ไม่มี login)
> 5. ยืมแล้วต้องมีวันกำหนดคืนทุกครั้งไหม? (ถ้าไม่บอก ถือว่ามี และเกินกำหนดต้องเห็นเป็นสีแดง)
> 6. ถ้าเลิกใช้ของที่เคยถูกยืม ประวัติเก่าต้องยังอยู่ไหม? (ถ้าไม่บอก จะซ่อนแทนลบ)

**รอบ 3** — M3 (สิ่งที่ไม่ทำ), M11, M12+M13
> 7. รอบแรกผมจะยังไม่ทำ login, แจ้งเตือนเกินกำหนด, รายงานสรุป — มีอะไรใน 3 อย่างนี้ที่ขาดไม่ได้ไหม?
> 8. วันแรกที่ใช้จริง คุณจะลองทำอะไร 3 อย่างเพื่อเช็คว่าใช้ได้? (ถ้าไม่บอก ผมใช้: ยืมจนหมดแล้วยืมไม่ได้, คืนแล้วยืมได้อีก, ดูรายการค้างบนมือถือ)
> 9. มีรายการของเดิมใน Excel ที่ต้องเอาเข้าไหม กี่รายการ? (ถ้าไม่บอก ถือว่าเริ่มจากว่าง)

→ M1/M4/M7 ครบจากข้อ 1–3, ข้ออื่นมีคำตอบหรือค่าเริ่มต้น (M13 deploy และ M14 สไตล์ไม่ได้ถาม ใช้ Render + โทนเรียบ) → สรุป 9 ข้อ + สมมติฐาน (กดพร้อมกันใช้กติกา P1, timezone ไทย, Render, โทนเรียบรอเคาะจริงตอน Task Design) → รอยืนยัน → เขียน
