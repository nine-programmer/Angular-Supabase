# Template Scope — ระบบแบบไหนสร้างบน template `Angular-Supabase` ได้

อ่านใน step 1 ของ SKILL.md **ทุกรอบ** (รอบแรกและรอบ feature) ก่อนสัมภาษณ์ — ไฟล์นี้เป็นที่เดียวที่เก็บตารางขอบเขต; `docs/ARCHITECTURE.md` ข้อ 10 มีแค่เกณฑ์ตัดสินเร็วและชี้มาที่นี่

Template นี้ออกแบบสำหรับ **mini app ต่อลูกค้า 1 repo** ที่เป็น "กรอกข้อมูล → เก็บ → ดู → เปลี่ยนสถานะ" โดยทุกอย่างผ่าน API ที่ server ตัวเดียว

| ระดับ                                                    | ตัวอย่าง                                                                                                                                                                                                                                                                                                                                   | ทำอย่างไร                                                                                 |
| -------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------- |
| **พอดี** — ไม่ต้องคิดเพิ่ม                               | ยืม-คืน, จองคิว, ลงทะเบียน, สต็อก, ทะเบียน/รายการ, ใบขอ-อนุมัติ, แจ้งซ่อม, จองห้อง, บันทึกเข้างาน                                                                                                                                                                                                                                          | ใช้ pattern ใน skill (P1–P6) หรือ pattern ที่ใกล้เคียงที่สุดได้เลย                        |
| **พอดี แต่ต้องตัดสินใจใน SYSTEM_SPEC 2.4**               | login/หลายบทบาท (middleware ใน `src/server/`) · resource > 5 (`src/server/features/`) · อัปโหลดไฟล์ (server → Supabase Storage ในไฟล์เดียว สลับเป็นดิสก์/S3 ได้เมื่ออยู่บน VPS) · ส่ง LINE/อีเมล (server เรียก API ภายนอก) · งานตามเวลา (`pg_cron` — บน VPS ต้องติดตั้งเอง — หรือ endpoint ให้ cron เรียก) · รายงาน/CSV (server สร้างไฟล์) · หน้าจออัปเดตเอง (polling; ถ้าต้องเร็วกว่า 5 วินาที ใช้ SSE จาก Express) | เขียนวิธีที่เลือกไว้ใน SPEC 2.4 — ที่วางไฟล์ของแต่ละแบบกำหนดไว้แล้วใน `docs/ARCHITECTURE.md` ข้อ 9 (ไม่ต้องถามผู้ใช้เรื่องโฟลเดอร์) — ยังไม่ให้ browser แตะ Supabase |
| **ไม่พอดี** — ต้องอัปเกรด template หรือใช้ template อื่น | realtime หนัก (แชท, ติดตามตำแหน่งสด) · mobile native / offline-first · SaaS หลายลูกค้าใน DB เดียว (multi-tenant) · เปิด API ให้บุคคลที่สามเป็นหลัก · traffic สูงจน SSR + API ใน Node ตัวเดียวไม่พอ                                                                                                                                         | **ห้าม** ฝืนยัดลง SPEC 2.4 — เป็นการตัดสินใจระดับ template: เสนอผู้ใช้ให้ (ก) ตัดความต้องการนั้นออกหรือแทนด้วยวิธีระดับ "พอดี" หรือ (ข) เปิดรอบ feature ของ template เอง (`docs/ARCHITECTURE.md` ข้อ 10) ก่อน แล้วค่อยกลับมาเขียน spec นี้ |

เกณฑ์ตัดสินเร็ว: ถ้าวิธีที่ "เป็นธรรมชาติ" ของความต้องการนั้นคือให้ browser คุยกับ Supabase โดยตรง (Realtime, Auth ฝั่ง client, Storage ตรง) แปลว่าอยู่นอกกรอบของ template นี้
